# Проект: Микросервисная Платформа "Smart Home"

Этот проект представляет собой комплексную систему, построенную на принципах микросервисной архитектуры. Он включает в себя два основных бизнес-домена:
1.  **`telemetry`**: IoT-платформа для сбора, агрегации и анализа данных с датчиков умного дома.
2.  **`commerce`**: E-commerce платформа для продажи устройств и компонентов умного дома.

## Структура Проекта

Проект организован в виде мульти-модульного Maven-проекта со следующей структурой верхнего уровня:

*   **`telemetry`**: Модуль, объединяющий сервисы для обработки телеметрических данных.
*   **`commerce`**: Модуль, содержащий сервисы для поддержки продаж (интернет-магазин).
*   **`infra`**: Модуль для инфраструктурных компонентов. Здесь располагаются **API Gateway**, **Service Discovery (Eureka)** и сервер конфигурации (**Spring Cloud Config**).
*   **`interaction-api`**: Общая библиотека, содержащая DTO-объекты для межсервисного взаимодействия (входит в **`commerce`**).

## Архитектура и Инфраструктура

Проект следует ключевым принципам современной облачной разработки:

*   **Микросервисная архитектура**: Каждый сервис является независимым и развертываемым компонентом.
*   **API Gateway**: Реализует шаблон "Шлюз API". Модуль `API-Gateway` служит единой точкой входа для всех внешних клиентов. Он отвечает за маршрутизацию запросов к соответствующим микросервисам, а также может брать на себя сквозные задачи, такие как аутентификация, логирование и ограничение скорости запросов.
*   **Database per Service**: Каждый сервис владеет своей собственной базой данных.
*   **Service Discovery**: Используется **Eureka** для динамического обнаружения сервисов в сети.
*   **External Configuration**: Конфигурация сервисов вынесена вовне с помощью **Spring Cloud Config**.
*   **Асинхронное взаимодействие**: Для обмена событиями используется брокер сообщений **Apache Kafka** (в модуле `telemetry`).
*   **Синхронное взаимодействие**:
    *   **gRPC**: Для высокопроизводительных бинарных вызовов (в модуле `telemetry`).
    *   **Feign Clients**: Для декларативного REST API взаимодействия между сервисами (в модуле `commerce`).

## I. Модуль `telemetry` (Платформа "Умный Дом")

Эта часть системы отвечает за обработку данных с устройств умного дома в реальном времени.

<h4> Collector</h4>
Сервис-сборщик, принимающий события от устройств через gRPC (в формате `Protobuf`) и отправляющий их в топики Kafka.

<h4> Aggregator</h4>
Агрегирует данные из Kafka, создавая "снапшоты" текущего состояния каждого хаба. Публикует снапшоты в новый топик Kafka (в формате `Avro`).

<h4> Analyzer</h4>
"Мозг" системы, реализующий логику сценариев.

* **Потребляет данные** из топиков со снапшотами и событиями конфигурации.
* **Хранит сценарии** в своей базе данных.
* **Анализирует** состояние хабов и, при выполнении условий сценария, **отправляет команды** на устройства через gRPC-вызовы.

## II. Модуль `commerce` (Интернет-магазин)

Эта часть системы реализует полнофункциональный интернет-магазин.

### Описание сервисов

<h4> Shopping Store</h4>
Отвечает за каталог и управление витриной товаров.

* CRUD-операции для товаров.
* Получение списка товаров с пагинацией и фильтрацией.
* Получение детальной информации о товаре.

<h4> Shopping Cart</h4>
Управляет корзинами покупок пользователей.

*   Добавление, удаление и изменение количества товаров в корзине.
*   Отображение актуального состава корзины.
*   Деактивация корзины.

<h4> Warehouse</h4>
Управляет складскими запасами и резервированием.

*   Приёмка и добавление товаров на склад.
*   **Сборка товаров для заказа**: проверка наличия, уменьшение остатков.
*   **Передача товаров в доставку**: связывание собранного заказа с идентификатором доставки.
*   **Возврат товара**: увеличение остатков на складе.

<h4> Order</h4>
Обеспечивает управление жизненным циклом заказов.

*   Создание нового заказа.
*   Расчёт стоимости доставки и итоговой стоимости заказа.
*   Управление статусами заказа: оплата, сборка, отгрузка, ошибка, возврат.
*   Получение списка заказов для клиента.

<h4> Payment (Эмулятор платёжного шлюза)</h4>
Сервис-адаптер, скрывающий логику интеграции с реальными платёжными системами.

*   **Расчёт стоимости товаров**: получает цены из `shopping-store`, суммирует их.
*   **Расчёт итоговой стоимости заказа**: `(Стоимость товаров + 10% НДС) + Стоимость доставки`.
*   **Сохранение информации об оплате**: сохраняет в БД детали платежа со статусом (`PENDING`, `SUCCESS`, `FAILED`).
*   Предоставляет эндпоинты для "платёжного шлюза", чтобы обновить статус оплаты на `SUCCESS` или `FAILED`, что, в свою очередь, обновляет статус в сервисе `order`.

<h4> Delivery (Эмулятор сервиса доставки)</h4>
Сервис-адаптер для взаимодействия с внешними службами доставки.

*   **Сохранение сведений о доставке**: сохраняет в БД детали (объём, вес, адрес, статус) и возвращает `deliveryId`.
*   **Расчёт стоимости доставки**: использует сложный алгоритм, учитывающий адрес склада, адрес клиента, вес, объём и хрупкость товара.
*   **Приём товаров в доставку**: меняет статус доставки на `IN_PROGRESS` и вызывает методы в сервисах `order` (меняет статус заказа на `ASSEMBLED`) и `warehouse` (связывает `deliveryId` с заказом).
*   Предоставляет эндпоинты для обновления статуса на `DELIVERED` или `FAILED`.

## Технологический стек

*   **Язык**: Java 21
*   **Фреймворк**: Spring Boot 3.3.*, Spring Cloud 2023.0.3
*   **Межсервисное взаимодействие**: Feign Clients (REST), gRPC, Apache Kafka
*   **Инфраструктура**: API Gateway, Eureka, Spring Cloud Config
*   **Форматы сериализации**: Protobuf, Avro, JSON
*   **Базы данных**: Реляционные (PostgreSQL) по принципу Database per Service.
